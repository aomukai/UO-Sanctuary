# GenericPet full AI-entry orchestration

2026-11-09 JST. Reference: **D2R Reign of the Warlock 3.3.93847**. Coverage remains **213/240 handlers, Warlock 4/30; no class certified**. The complete captured AI entry now has a prepared C# implementation, and original demon event tests pass through it into the existing root. Live helper, birth/control and host-clock bindings remain unfinished.

`GenericPetAiEntry` follows all branches of `43b0c0` (1,096 bytes), rather than calling the root directly from an event. It captures the controller and game/unit parameter snapshot, fetches both metadata rows in source order, selects the initial special override, preprocesses, obtains the target-policy type, prepares targets where required, runs the post-target stage, processes queued predicates/actions and invokes the selected special/default function. The current GenericPet descriptor uses target type 0, preserving its existing root's own targeting; that does not make other target modes or special overrides implicit no-ops.

The game snapshot consists of the raw +108 word and +104/+106/+101 bytes plus one caller-stack byte that the original leaves unwritten. This byte is an explicit input, with no inferred gameplay meaning. A flagged monster snapshot uses the eight bytes at monster-data +8c. The first metadata lookup uses the original game selector/class, while the second reads them again. Preprocessing can change the tick control; the initial override still governs an early fallback, while the final invocation reads the tick's current override and default function.

Target modes 1/3 use the same source helper with distinct boolean input. Modes 2, 5 and 6 retain their separate caller paths, including the different null-target fallbacks. Early special callbacks accept raw flags 0/2/6 and exclude 4. Missing metadata returns early; missing required control or a null default call is explicitly refused instead of inventing a controller or silently continuing.

Queued actions retain FIFO order, predicate rejection, append behavior, logical closure release and the executing flag. The queue-processing control reference is cached as in the source. The queued helper receives the original actor, command and **AI control**, not the tick frame. The final invocation reads the current default function after queued actions. Managed lifetime supports a stable head and returning handlers; raw heap/functor relocation, arbitrary invalidation, exceptions and reentrancy are not certified. Constructors require explicit control values and queue inputs, so no authentic startup defaults are implied.

**Reference verification:** 57 focused offline/native comparisons execute the complete entry with explicit metadata, preprocessing, targeting, override and queued services plus a declared stable inline-functor ABI. They cover both snapshots, the unwritten tail, metadata mutation/order, every target-policy branch, early exits, control/override replacement, override flags, FIFO rejection/release/append, updated default functions and missing-control/null-function refusal. Refusal controls compare trace/controller state; the missing-control frame is not returned by the C# API and is not asserted as an observed frame. These comparisons do not certify the declared helper internals or the entire live AI controller.

The first probe incorrectly expected the queued helper's third argument to be the tick. Source review established that it is the control pointer. The exact initial script/log are archived under `.local/class-skills/pet-ai-entry-source/probe-diagnostics-1`; the corrected service signature preceded builds/native tests.

Five previously missing direct callees are now captured completely in one bounded read: preprocessing `43a6c0` (544 bytes), descriptor selection `439fe0` (187), target helpers `424e60` (454) and `425030` (383), and post-target `43af30` (390). This read consumed 4,476 bytes including validation. The collector explicitly validates the entry's seven inline jump-table values and excludes those bytes from instruction parsing; it does not treat disassembled data markers as executable instructions or weaken the shared capture tool. These helper bodies are retained for subsequent integration; they are not all executed by the entry-only comparison.
