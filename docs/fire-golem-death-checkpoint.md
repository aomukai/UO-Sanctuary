# Fire Golem delayed death checkpoint

Reference: **D2R Reign of the Warlock 3.3.93847**. Approved Sanctuary deviations take precedence. This candidate is isolated from the installed server and existing saves; it does not complete Necromancer or another class.

New learned casts create `FireGolemDeathBody`, a saved subtype of the existing exact-resource Fire Golem. Natural death and successful golem replacement perform normal NPC death bookkeeping, then retain the **original** registered actor and owner for four frames (160 ms). The actor is dead, frozen and excluded from the live roster; pending contact, AI and aura are stopped. A monotonic timer bounds the live delay, with a UTC expiry for reloads. There is no substitute caster or player proxy.

The expiry emits the source's fixed **100 physical + 100 fire** packet using existing Sanctuary mitigation and health services. Each recipient receives its own intrinsic 5% critical roll; critical doubles both channels and consumes its draw even when missile blocking succeeds. This is separate from weapon damage, Enchant and owner gear. Missile117 requests no ordinary hit recovery. Owner credit remains available after the original source is finally deleted.

The source review executes 5,184 controlled complete callback/radial/owner/result/critical/resistance/events/health contexts. See the [source review](fire-golem-death-source-review.md) and [source receipt](../tools/reference/fire-golem-death-source-evidence.json). These are supplementary legacy source observations, corroborated where possible against the pinned current tables; they do not prove current executable equivalence.

Nine connected burst phases cover three scenarios on each boot. Four item/Thorns audit markers, all 71 Python tests, 573 unchanged named availability decisions and both clean builds pass with zero warnings/errors. Runtime data, the staged kernel and 106 installed artifacts remain unchanged; current fingerprints are 845/21. Both native jobs finished successfully. See the [native receipt](../tools/reference/fire-golem-death-native-evidence.json). The candidate checks natural damage, real Clay replacement, mixed resistance, blocked-recipient critical draw order, exact kill credit, no early damage/deletion and no added hit recovery. Its persistence fixture holds only the original actor’s volatile retirement clock for 60 seconds through test-only reflection, spanning asynchronous heap preparation. The real saved UTC expiry remains unchanged and expires before restart. This verifies serialization/restoration and offline expiry; it does not demonstrate a snapshot within the unmodified live 160 ms window. The separate connected tests verify that normal deadline; production code and the kernel contain no hold. Reload checks require observation of that same serial in its dead registered state, expiry without offline damage replay, cleanup and unchanged previous `FireGolemBody` v0 type/ownership.

It now explicitly waits for and counts those results. Failed wrapper attempts are not counted as completed acceptance.

Optional monster-fire/noRatio behavior, mode-entry RNG, initial aura scheduling, full initializer/world/client acceptance and the remaining Necromancer curse checks stay open.
