# Saved player item-proc host

Reference: **D2R Reign of the Warlock 3.3.93847**, approved Sanctuary deviations first. Registered proc fields now belong to their original item, while source RNG and event-registration history belong to each player. The host composes the existing stat graph, source event list, bindings, protected item frames and Fire Ball controller. **Full original-item proc projection, initial player seed acquisition, normal combat phase hooks and whole Hellslayer/golem admission remain unfinished.** No item becomes acquirable and no class talent is newly admitted.

`PlayerItemProcProfiles` adds the new version-zero `SanctuaryPlayerItemProcs` profile (ID257), pinned to3.3.93847. It saves immutable event-only item providers, each player's independent raw source seed, active attachment/damage flags and the complete event list including IDs/order. Missing actor initialization is refused rather than seeded implicitly. Reinitialization cannot reset an existing stream; original provider fields cannot be replaced or rerolled. These fields are real native profile data, unlike the earlier fixture-only carrier manifests. They still describe explicitly enrolled event-only carriers, not a complete Hellslayer GearState or complete equipment numeric graph.

`ClassGear.Refresh` updates subscriptions for enrolled players. Identified, intact, equipped providers use existing native eligibility. Actual source stat-cost damage flags let the shared damage-toggle kernel suppress offhand on-attack fields while retaining non-damage incoming fields. Equal skill/rank layers aggregate their chances and keep existing source registration history when the value stays nonzero. Trading the same original transfers its effects through actual ownership/equipment without rerolling its provider or resetting either player's stream. The host requires the exact source phase, UTC frame, uninterruptibility and world-allocation service. Default offline/internal/town admission refuses fighting before RNG; explicit action overrides are confined to component qualification.

**C1/I4/source4/run2 passes35native results, six retained learned Fire Ball wire inputs, eight authenticated connections, three saves and two actual reloads.** [Receipt](../tools/reference/player-item-proc-host-native-evidence.json). The new host family runs alongside the prior eight-class frame/producer, normal Sorceress and Iron Golem controls because equipment refresh and persistence are shared.

Two real players, three original converted carriers and the new native profile verify primary/offhand selection, additive chance, unchanged-refresh identity, identification, repair/backpack transitions and cross-class trade. Dispatch uses saved per-player LCG state and a separate explicit allocation seed. Melee and missile attack phases and incoming melee delivery reach actual projectiles/native life damage without owner mana payment. Offline refusal does not advance the stream. A throwing allocator retains the consumed source draw while closing event/frame scopes. Both reloads compare exact original parents/rolls/wounds/mana and the entire profile's seeds, attachment flags and event history; invalid provider data is refused atomically and returned snapshots cannot mutate live state.
