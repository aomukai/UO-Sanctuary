# Death Mark player action proposal

Reference: **D2R Reign of the Warlock 3.3.93847**. The approved recipient and native-world mappings remain in force. This proposal addresses the remaining player startup/context boundary; it does not reopen teleport, command, debuff, demon AI or flight decisions. **Prepared candidate; not yet approved or available through learned input.** Verification results will be recorded after the native run.

Proposed Sanctuary rule:

- Require a living, connected Warlock/Witch with Death Mark trained and at least one eligible original demon in the existing same-facet roster. Reuse the approved roster's ownership, parking and explicit unsupported-controller checks. Require the existing destination safety, visibility, LOS and 19-tile range policy before starting the shared Warlock SC/FCR windup. Recheck the actual roster and destination at release. The current `requirespettype` startup caller is unavailable; this check is an explicit adaptation.
- Spend no mana during windup. The ordinary SC clock, movement/weapon/status interruption, cancellation and transient player-session lifetime are shared with existing actions. Capture the animation clock at entry and evaluate the effective skill rank/table cost at release. Reuse the pinned ordinary missing-start/successful-do payment contract and 20-frame skill-local cooldown.
- At release, check available mana before invoking the existing do155/native-world composition. On source result 1, spend the fractional table cost once and start the cooldown. On result 0, spend nothing and start no cooldown. Claim the release before world callbacks so an interruption or repeated scheduler observation cannot replay it.
- Preserve do155's actual ordering: pet placement/commands can happen before a later recipient allocation fails. Such failure keeps the completed relocations and the old mark, with no payment or cooldown. Do not invent rollback. Unsupported contexts are logged and refused explicitly; a hypothetical resource change during nested world callbacks is also an explicit fault, not a silent refund or repeat.
- For learned native casts, use **0** for the opaque source unit field `12c` copied into mark metadata stat202. The qualified prepared caller still accepts an explicit value and the component proof preserves it. Current D2R's producer for this field is unknown; zero is a declared host adaptation. It does not replace rank, creator, target, duration or the already-approved damage/defense rules, and no current-source equivalence is claimed.
- Reuse the original three saved demon hosts after relocation. Keep birth snapshots, wounds, RNG, controller ownership and already-issued projectile lifetimes. Cancel unissued intrinsic actions through the existing neutral-mode notification, then let each original host observe its registered relocated position and resume its normal AI. Parking grants no healing or resets.

The learned route remains gated until this complete proposal is approved and its input integration is verified. Prepared tests use real connected owners and the production source-frame demon controllers; they do not claim Death Mark left/right/quick socket coverage. Existing real summon inputs are retained as regressions. PvP and other unsupported recipient/property domains remain explicit limits rather than new guessed rules.

The integrated scene also exposed a defect in the existing native flight mapping: source placement pattern2 checks a cross, while the approved native flying movement samples a full3x3 box. Native flying placement now retains the original source search/order and additionally checks that approved full box, so diagonal hostile occupancy cannot admit an immediately invalid landing. This implements the already-approved flight-world footprint rule; it is not a new gameplay decision or a change to the shared source search kernel. Ground placement remains unchanged.

No new timer, persistence ID or serialization version is required. Pending player actions are transient. The shared cast sound0x1E5, landing0x3728 and mark0x375A are identified placeholders; final cast/warp/mark/expiry/audio and talent/left/right/quick icons remain in separate asset registers.
