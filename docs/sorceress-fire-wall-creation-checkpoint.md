# Fire Wall creation source checkpoint

Reference: **D2R Reign of the Warlock 3.3.93847**, approved Sanctuary deviations first. The [Blaze native checkpoint](sorceress-blaze-checkpoint.md) remains the latest accepted gameplay build, commit `3949cd7`. This checkpoint prepares Fire Wall's replacement; it changes no C#, runtime data, installed server or saves and does not certify Fire Wall or a class.

The [source composition](../tools/reference/fire-wall-creation-source-evidence.json) executes **6,600 cases**: 5,760 cast/admission/factory combinations and 840 maker/factory combinations. Five complete older routines remain unchanged: do24, its target-collision admission helper, the missile factory, shared maker do6 and the previous-movement flag accessor. Source bodies are checked against the pinned older source tree; current skill/missile rows are checked against the retained 3.3.93847 manifest. Independent request/factory expectations and ASan/UBSan pass.

Do24 resolves selected-unit coordinates before path aim. Its helper requires an owner room, nonzero target coordinates and a clear size-based collision mask5 query. The callback then rejects a town target room, requests two flags33 makers at the center with opposite perpendicular targets, and requests the optional flags1 center field last. A factory service refusal does not cancel the other requests or turn the outer successful callback into failure. The current native prototype creates the center first and has no equivalent complete prepared admission.

Maker68 uses velocity2304 after the factory's 75% scaling, `CanSlow=0`, no initial steps and an evaluated lifetime `7 + 2 * rank`. Slow Missiles therefore does not reduce this maker's velocity. A maker aimed at its own position receives the complete factory's (+1,+1) target adjustment. When do24 is aimed at the caster, both maker requests have that same point, so both factory outputs aim along the same diagonal in this older chain. **Modern self-casting is uncorroborated.** The prototype instead invents a fallback axis and sends the makers in opposite directions; do not label that source-exact.

Do6 is already implemented and compared for Molten Boulder in `MoltenBoulderPackets.Trail`. It requires owner, row, a nonnegative child ID and a path. The previous flag8 emits a single flags33 child at the maker's current position **before** the generic movement/collision/lifetime service. It does not first move and then emit at the new point. This order also matters on the final update: a qualifying child request precedes terminal collision/lifetime handling. Zero child IDs remain valid requests in the complete routine. Negative rank is passed through by do24/do6/factory; the normalization previously observed for Blaze belongs to its emitter, not the factory. Zero-ID/negative-rank controls use declared row/formula services and do not establish the actual missile0 row or modern negative-rank behavior.

A separate [damage capture composition](../tools/reference/fire-wall-damage-source-evidence.json) passes **27,540 cases across all 255 ranks** with clean ASan/UBSan. Fifteen complete creator/add/scale, physical and elemental skill/missile getters, tier/mastery and stat-writer routines execute. The maker's packet is entirely zero despite deliberately unrelated stored skill and owner/origin item/weapon/critical noise. The field selects its own Skill51 row, applies hard Warmth4 plus Inferno1 percent after HitShift4, then fire mastery once, and stores no passive mastery or critical inheritance. These are supplied hard/formula/table/stat services, not modern binary or full factory/damage event acceptance.

Maker collision mode8 still uses the unit recipient callback and its own LastCollide flag. **Zero damage does not establish that the maker has no contact/event bookkeeping.** The native replacement must preserve that routing or identify unsupported event contexts; it must not turn the maker into a second damaging field or silently erase its collision contract. This resolves the numeric prerequisite while leaving the native routing work open.

The existing full [stationary field lookup/do5 proof](../tools/reference/immolation-field-engine-evidence.json) and [hit0 routing proof](../tools/reference/immolation-routing-engine-evidence.json) are relevant: Fire Wall69 has hit0, damage3, size1, 90 frames and DamageRate41. Blaze67 has hit8 and rate0. Reuse the existing source field03/flags/HP-return composition, but retain those row differences. The [Blaze damage proof](../tools/reference/blaze-damage-source-evidence.json) already contains controlled rate0/41 cases; it is not by itself full Fire Wall factory, fill-damage or hit routing acceptance.

Next implementation should replace the normalized-vector maker with the existing fixed-point `MissileVectors`/`SourceMissileSteps` services and reuse `MoltenBoulderPackets.Trail`, saved FireGround state, Immolation's first-recipient lookup and the shared ordered spell HP/return services. Maker updates and newly emitted fields must run in timestamp/ID order so a delayed tick cannot create every child before processing older field contacts. Each child retains the maker's skill rank and reads live hard-point/gear creation values; existing fields keep their captured packets. Historical rankless makers/fields must keep their old payloads/route without reconstructed path or RNG history.

The shared `InstantSpellNpcDamage` currently uses the default mitigation rate0. Fire Wall needs rate41 passed through that existing service, rather than duplicating damage or folding potion additions into scalar fire. Add native comparisons with nonzero supported MDR so the test actually distinguishes rate41 from rate0. `GemCombat.Reduction` has a supported original-item NPC path through `NpcEquipmentCombat` for bound Iron Golems; ordinary UO creature equipment does not silently provide that context. Keep direct adapter checks separate from natural hostile field delivery. Pure-fire ordinary shield block stays excluded; passive avoidance/PvP/special actor adapters remain explicit gaps.

Remaining verification includes prepared right-only cast/payment/selected-target resolution, local delay35, independent rank/hard curves, self-aim, creation order, previous-cell/final-frame emission, barriers and room/cell mapping, typed immunity/potion/MDR, harmless offline aging without replay, and two natural resumes of original saved makers and fields with wounds/resources/gear intact. Full modern expression/factory/stat/global seed, source animation RNG correlation, owner/facet/town lifecycle and graphical-client behavior remain unproved. No final art is needed to implement those mechanics: Fire Wall's existing cast/ground/contact/expiry/audio and separate talent/hotkey icon ledger entries remain pending placeholders.
