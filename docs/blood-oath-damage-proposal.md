# Blood Oath incoming-damage proposal

Reference: owned **D2R Reign of the Warlock3.3.93847**. **Prepared candidate;not yet approved or enabled for learned players.** Existing approved summon snapshots,lifecycle and difficulty policies take precedence. This proposes the missing incoming reaction,not a second pet life/resistance writer. Verification is recorded separately after the native run.

The owned378row names start66,`absorbresisteddamage`/event35,`calc1=dm12` and `calc2=3`. The saved candidate35capture has920unreadable bytes and no verified callback identity. The [pinned-version datamined reference](https://diabloforfans.com/skill/blood-oath?lang=enUS) corroborates the current data version but does not establish the callback. The user-provided Warren/Kabryxis notes,inspected through [their older PDF copy](https://upload3.inven.co.kr/upload/2026/03/02/bbs/WarlockSkillsNotesandFunctionality.pdf),report a different hard-point-only redirection result;their tested game version is unspecified. [Blizzard's3.1.2notes](https://news.blizzard.com/en-us/article/24271875/reign-of-the-warlock-3-1-2-patch-notes) confirm a historical lost-points retention fix,without specifying transfer arithmetic. The conflict stays explicit in [the source review](../tools/reference/blood-oath-source-review.json);no current callback has been inferred from those reports.

Proposed complete Sanctuary rule:

1. Use the **current effective Blood Oath rank** for the owner's reaction,including item bonuses. Use the pinned diminishing `dm12` curve:3%at rank1,25%at rank20 and30%at rank60. This is **one total budget per incoming hit**,not that percentage per demon. Read it anew on each hit;rank0,another active class,logout or an actual safe area grants no protection. Existing demons keep their separately approved birth life/resistance snapshots.
2. Derive the budget from settled positive FP8 direct damage after the existing mitigation,shields,ordinary damage-event handlers and native final-damage adjustments,immediately before owner life commitment. A fully shielded hit transfers nothing. This preserves the established event/leech chronology rather than replaying callbacks. It explicitly replaces the unavailable start66/event35registration and callback semantics.
3. Use up to **three** actual living,damageable,permitted,original learned demons on the owner's current facet,ordered by the existing saved creation ledger then serial. Parked,other-facet,dead,deleted,invulnerable and inactive pets do not contribute. Require their qualified source controllers and known native incoming wrappers;unsupported legacy/equipment/modifier contexts log and refuse instead of gaining guessed protection. The three-recipient interpretation of `calc2` is an adaptation,not a recovered caller.
4. Compute `floor(settledDamage256 * percent / 100)` once. Divide it evenly among selected recipients,assigning remaining FP8units in creation order. Cap each assigned share at that pet's current life. Keep unabsorbed or invalidated shares on the owner;do not redistribute them or grant cover beyond that pet's available life. Preserve the existing below-one-life death threshold and its fractional rounding.
5. Apply the shares as already-settled life damage,**bypassing the demons' resistance,immunity,armor and shield calculations**. Reuse `SkillHealth` with its non-attack return kind and the actual original attacker for normal damage/death credit. Generate no new weapon/skill hit,leech,Crushing Blow,Open Wounds or recursive sharing packet. Existing native notifications and death cleanup still occur;per-owner reentrancy is guarded.
6. Reduce the owner hit only by successfully assigned/transferred amounts. Recheck recipient eligibility before delivery. If an unsupported native callback changes its expected life loss,log/refuse the context and retain the original owner hit. Already-completed transfers are not rolled back;no new unverified protection is granted. This exceptional partial-mutation behavior remains visible in diagnostics.
7. Direct hostile incoming hits may use this path. Exclude self costs,self/friendly sources,anonymous environmental damage,periodic poison/burning ticks and return damage. These exclusions and the exact phase are explicit Sanctuary rules;the opaque current callback does not establish them. Native resisted and armor-ignore hits both use the existing fractional health bridge;no native rebuild is required.
8. Keep reaction derivation transient. Existing player skill/gear saves and original pet ownership/birth/wounds/RNG/controllers already persist what it needs;do not serialize a new passive registration or replay offline hits. Future Bind Demon protection requires its own qualified actor/receiver and remains part of that unfinished skill;no generic UO creature is silently admitted now.

Only internal prepared test leases activate this candidate. Normal learned Blood Oath remains unavailable until this whole rule is explicitly approved and the automatic route is verified. This is a native host adaptation,not a claim of exact current D2R event35/start66/global ordering or complete PvP/recipient/property/client equivalence.

No new timer,persistence ID or serialization version is needed. The passive talent-tree icon remains pending,with its text-label placeholder and no active hotkey. There is currently no invented transfer beam or cast animation. Any final passive/transfer/audio presentation,including the source sound's unverified trigger timing,stays in the separate effects register.
