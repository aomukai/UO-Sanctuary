# Skeleton component and shield source review

Reference: **D2R Reign of the Warlock 3.3.93847**, with approved Sanctuary deviations taking precedence. This review records a nonblocking uncertainty discovered while connecting regular skeleton combat. The [review receipt](../tools/reference/skeleton-components-review.json) hashes the current skill/monster/component data and complete inspected older-engine bodies. It is static review, not compiled execution or observation of the modern executable.

Current Raise Skeleton skill 70 has Param1=5, described as a shield-spawn percentage. The older complete do31 caller checks effective rank above 2 before drawing the owner's random stream modulo 100 and comparing with Param1. It passes that boolean to `D2GAME_SetUnitComponent_6FD0C3A0`.

That helper does not independently decide whether the final pet has a shield. Earlier, `MONSTER_SetComponents` either copies a regional appearance variant or randomizes twelve components from the pet's stream. The skill helper leaves component 7 untouched when its boolean is false. When true, it overwrites component 7 using the cosmetic-level table. Its default cosmetic level is 1, whose shield index is 0 (`nil`). A full-set modifier can supply another cosmetic level. Treating Param1 as a final 5% chance of a shield would therefore silently invent behavior and disregard the initial component choice.

The pinned regular skeleton component pool is `nil,buc,lrg,kit,sml`; its base block is 3 in each difficulty. The complete older `UNITS_GetBlockRate` inspects the final shield component's item type unless an innate or named special exception applies. Thus final component selection has a mechanical effect. Cosmetic art can remain a placeholder, but the underlying shield identity must eventually be represented and saved.

Still needed: current initializer applicability and regional appearance pool provenance, the full-set cosmetic-level path, exact owner/pet draw order, final component/code classification and persisted blocking through actual incoming attacks. Do not replace this gap with either the parameter label's apparent meaning or a guessed uniform final distribution. Existing generic/native presentation and shield suppliers are not certified by this review.

The previously verified shared `NecromancerPetAi` policy already compares 1,598 complete older-source contexts for both melee and ranged branches. A regular skeleton world consumer can reuse that policy and the Iron Golem's motion/contact primitives after checking SK animation/action clocks, unarmed damage/critical composition, seed ownership and lifecycle. That implementation remains separate from this review. The source data identifies intrinsic Crit=5; ordinary regular-skeleton delivery still needs acceptance.

This is recorded in the separate [observation record](../tools/reference/skeleton-shield-observations.json); it corroborates visible shields, not a final distribution or measured block rate. The hashed static review remains unchanged. Continue unaffected mechanics while initializer/component persistence stays uncertain.
