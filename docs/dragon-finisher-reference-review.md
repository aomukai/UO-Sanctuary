# Dragon finisher consumption review

Reviewed2026-11-03. Mechanical baseline remains **D2R Reign of the Warlock3.3.93847**; approved Sanctuary deviations take precedence. This records evidence for the next implementation step and enables no handler.

The owned current installation's `dataguide/data/files/skills.js` describes `prgchargesconsumed` as the number of progressive charges consumed when an attack hits an enemy. The current Dragon rows retain value1. That description supports consumption at successful contact, rather than assuming every contact of a multiple-hit animation shares one debit. It does not itself identify the exact current result/block dispatcher.

Blizzard's [released2.4 notes](https://news.blizzard.com/en-us/article/23788293/diablo-ii-resurrected-patch-2-4-ladder-now-live) introduced consumption of one charge per family instead of clearing the entire stack, and charge-conditioned guaranteed hits for the four Dragon finishers. Its cast-oriented wording alone is insufficient to choose the per-contact behavior of Talon or Claw.

Two firsthand reports in the [April27/November14,2022 Talon thread](https://us.forums.blizzard.com/en/d2r/t/bug-24-dragon-talon-consumes-charge-per-kick-not-per-cast/123875) describe successive kicks spending successive charges. The original reporter gives a rank12,three-kick example that consumes three charges. This is post-release2.4 observation, not a3.3.93847 test or an official bug disposition.

The [January24,2023 discussion](https://us.forums.blizzard.com/en/d2r/t/martial-arts-assassins-still-need-a-little-more/153677?page=2) contains a useful explicit recheck rather than only theory. Kabryxis reports testing Dragon Claw with two Phoenix charges and seeing the lightning and meteor effects with both charges removed. A three-charge test leaves one charge after Claw. The same participant describes Tiger's successive3then2 bonuses and Talon's per-kick consumption. An earlier opposing reply in that thread is subsequently corrected after its author learns about the2.4 change; do not cite that earlier reply as current behavior.

**Next action:** use per-successful-contact consumption as the evidence-supported implementation plan for ordinary non-Mosaic Talon/Claw contacts, reusing the existing consume-one charge service. Keep the age of the firsthand tests explicit. Verify how the complete legacy contact/progressive/scheduler paths compose with the current row, rather than waiting for another unavailable player playtest or importing the old full-stack removal policy. No assumption about failed/blocked contacts, Mosaic preservation, current charged block/dodge bypass or exact scheduler timing follows from those reports.

The remaining independent gates include modern charged hit/result ordering, action/rewind rates, complete kick packet/proc delivery, cancellation, payment and native input/persistence acceptance. The current game's process was closed at review time; incoherent static candidate callback bytes are not current code evidence. These individual limits continue to permit work on unaffected skills. Talent/hotkey icons and final effects/audio remain separate pending assets.
