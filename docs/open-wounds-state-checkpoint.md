# Shared Open Wounds keeps the first application when refreshed

Reference: **D2R Reign of the Warlock 3.3.93847**, approved Sanctuary deviations first. This increment follows `a181c0f`. It corrects the shared wound arithmetic/state needed by Blood’s pending unlock; **it does not enable Blood’s NPC Open Wounds or Life Tap**. No class is complete.

Before implementing an NPC callback, reviewed the existing named-item Open Wounds formula, shared `TimedEffects.Bleed`, NPC event registry and prepared source-damage/target-damage/HP phases. The older complete callback and state factory exposed two host mismatches: a first application’s creator/rate was overwritten on refresh, and the level formula capped at 99 although the callback only imposes minimum 1.

[The source probe](../tools/probe_open_wounds.py) reuses Battle Cry’s declared unit/stat/event/storage services without executing or replacing that earlier producer. It composes the complete unchanged tier routine, function 15 callback, shared state factory and actual percentage routine from the pinned older tree. **50,400 callback/factory contexts and 20 factory gates pass ASan/UBSan.** Cases distinguish chance success from actual state creation. Positive chance draws once even at 100%; NPC/attackability/row rejection comes afterward. Payload is 200 frames, negative HP regeneration, noncurse state 62, skill 0/rank 1. Curse resistance and Attract do not suppress this state.

The same-state/skill/rank factory result refreshes expiry but retains first creator/rate; stronger old rank rejects and a different skill replaces. The ordinary host wound producer always uses fixed skill 0/rank 1 semantics. `TimedEffects.Bleed` now settles elapsed work and, while active, resets only the remaining 8000 ms. It preserves first source/rate and accrued fractional damage. After expiry, a new application acquires the new source/rate and starts with no remainder. The generic scheduler, whole-HP transport, native callbacks and actual item trigger remain otherwise unchanged.

`NamedCombat.OpenWoundsDamage` retains minimum level 1 and existing integer player-quarter/ranged-half/elite-half arithmetic, while removing the upper 99 cap. A pure target-category overload lets native comparisons use source-supplied categories. Actual target classification still uses the existing host elite adapter; this is arithmetic verification, not proof of every species flag or PvP receiver.

**Build 1 / run 1 / audit 1 passes 307 native markers across three boots, two reloads and three saves**, retaining all 301 predecessor marker scopes. Native arithmetic matches 6,840 source-produced new-state cases through level 127. Deterministic controls verify fractional refresh, extended expiry, first source/rate, replacement after expiry, regeneration suppression/release, invalid inputs and actual The Gnasher item `AfterStrike` use.

One saved wound retains its clock/source/rate/fraction through both reloads; controlled later refreshes preserve the original application. Only that observation clock is held one hour, with unchanged persistence fields. Three connected real-item sessions use normal automatic ticking, refresh from a second source, retain the first rate, and expire after the renewed eight seconds. Physical immunity does not suppress the existing bleed transport in those sessions. Full negative-regeneration equivalence is not inferred from that result.

Both clean builds, four audits, 71 Python tests, 573 named definitions and eight-class/240-skill checks pass. Audit decisions remain unchanged with 879/21 fresh fingerprints. Pre-build/native/audit source/data and five tested DLL inventories match; runtime data, timed-effect record shape, staged kernel and 106 installed hashes are unchanged. No deployment/save reset; 186 handlers / Necromancer 30.
