# Proposed player melee item-proc world rule

Mechanical reference: **D2R Reign of the Warlock 3.3.93847**; approved Sanctuary deviations take precedence. The source event order and callbacks are reused. Current player unit-allocation chronology and the relevant uninterruptible-state mapping remain unverified. **This proposal is prepared and gated, not an approved claim of D2R parity.**

Adopt one world binding for the existing `PlayerWeaponContact` pipeline:

- When an online, living player with an active registered original proc provider releases a qualified melee contact packet outside town, retain its actual monster target and timestamp. Initialize that player's proc stream once if absent, using one unit-seed allocation from the existing saved Sanctuary world stream. Existing player streams are retained. Releasing a packet may initialize the actor even if later range/contact checks refuse damage; it does not roll a proc chance or allocate a projectile without a dispatched eligible phase.
- Dispatch `domeleedamage` at the existing successful damage-event boundary before life commitment, after existing Crushing Blow handling. Dispatch `domeleeattack` at the existing later attack-attempt boundary. Preserve the caller's actual result/hit flags. Do not manufacture HitFlags32 for misses, shield blocks or dodges. A fully absorbed successful contact retains both source phases. An out-of-range release dispatches neither.
- In this qualified ordinary melee route, permit item casts without replacing or cancelling the current player action, including a committed Zeal series. Do not infer the D2 uninterruptible bit from Sanctuary's input lock. Other player routes remain outside this rule.
- Use the player's saved source stream only for callback chance rolls. Each successful projectile allocation uses a separate unit seed from the existing saved world allocation stream; host entropy initializes that world domain only if it does not already exist. Reuse the current source LCG and profile rather than adding a second RNG system. This is Sanctuary's persistent-world policy, not recovered D2 game/map allocation chronology.
- Use the existing protected temporary item frame and Fire Ball producer. Item casts do not pay player mana, change ordinary bindings/targets or gain extra effective skill ranks. Preserve current hard synergy/mastery handling, projectile saves, credit, lifecycle and identified effect/audio placeholders.

The candidate verifies native damage and real learned Zeal through these actual hooks, plus exact phase/RNG behavior, misses/blocks/dodges, zero-life contacts, range refusal and two reloads. The proposal's implementation supports only already-qualified registered Fire Ball event providers. It does **not** admit Hellslayer, manufacture a complete named GearState, supply normal basic-attack/missile/incoming callers, enable other proc bodies or finish automatic Iron Golem registration. Full original-item qualification remains required before named acquisition.

`PlayerItemProcWorld.Approved` stays false. An owner-specific, transient scope is used only by the isolated qualification fixture and is closed before saving. The prepared candidate and retained regressions are described in [the checkpoint](player-item-proc-world-checkpoint.md). Approval would enable this world rule; normal online input should then receive its own qualification under the adopted rule.
