# Bind Demon native host eligibility audit

**Accepted: C1/I2/S3/N2; 18 native markers, three authenticated connections, three boots/saves and two reloads.**

Reference remains **D2R Reign of the Warlock 3.3.93847**. This closes a prepared-host eligibility bug and records actual current-world limits. It does not implement an invented native elite model or enable learned Bind. Coverage remains **226/240 handlers, Warlock 17/30; no class certified**.

Prepared Bind previously accepted a native Paragon flag as ordinary quality. It now shares Revive's existing unclassified-Paragon policy through `NamedCombat.NativeQualityIssue`; Revive's message and behavior are unchanged. Explicit native elites also refuse pending a qualified quality/stat adapter. The original living body, AI, wounds, mana, baselines and prior bound demon remain untouched when qualification fails. A native `IsParagon` transform, direct host qualification, binding and channel startup are checked against those invariants; two reloads retain the ordinary original demon and unowned Paragon flag. Wild regeneration is not represented as parked-pet recovery.

The audit enumerates concrete registered native types using current creature profiles and the exact existing Exorcism Slayer type predicate, without constructing every monster. Across 730 creature definitions, it finds 35 native demon type candidates: 22 have compatible source data and thirteen lack a pinned Bind species row. It records each demon classification, reward/species reference and whether the pinned row and all difficulty projections are compatible. **Source compatibility is not proof of live eligibility:** ownership, native controllers, current flags, typed endpoints, damage and life context still require per-actor checks. Missing species are reported rather than remapped by appearance or guessed relative strength. The current `EncounterCreature` profile is explicitly undead and non-demon, so that separate elite system does not currently supply Bind targets.

The Sunder provider review includes **eighteen** unique-item variants. Twelve use `cm3`; six renewed recipe-only variants use `cs2`. The original charm exclusion covers `cm1/cm2/cm3`, not `cs2`. Native acquisition checks establish that none of the eighteen is currently available. The `cs2` variants remain blocked as non-random source-recipe definitions; this is a distinct boundary, not proof that every future charm is covered by the old exclusion. Nonzero Sunder delivery remains unsupported and must be resolved before acquisition is enabled. This audit neither adds a reducer nor reinterprets the stored 300 value.

The native fixture manifest preserves the detailed type and Sunder-source inventory. Original Revive facet and NPC resource controls run alongside it. C1/I1 compiled clean; N1 stopped because its audit incorrectly required every charm to use the older bases. Its exact source, assembly and log archive is retained under `native-1`. I2 distinguishes the renewed recipe base and records explicit availability. Production C1 is unchanged for the accepted rerun. The combined [Bind action/world proposal](bind-demon-world-rule-proposal.md) now gives a reviewable definition for the qualified original-body path, while retaining native quality/species/sunder/underling gaps explicitly. It does not claim a full class certificate or erase those roadmap items. Four earlier Blood Oath, Engorge, Blood Boil and Consume proposals remain pending and unchanged.

No new timer, profile, serialization version, client/native build, installation, live D2R capture or artwork. Existing server artifacts, configuration, saves and prior client patches stay protected; the isolated patch-44 client is unchanged. Effects and icons require no new entries for this eligibility check and remain in their separate registers. No imagegen.
