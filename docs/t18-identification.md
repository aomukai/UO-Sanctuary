# T18 — Identification and information boundaries

Implemented and deployed20 October2026 JST. The user selected single-use Identify scrolls first and deferred charged tomes to T34.

A scribe's pen provides **Scribe Identify scroll**, also available in the native Utility scrolls menu. The recipe consumes1BlankScroll+1BlackPearl and one pen use per committed attempt, with normal native0–50 Inscription success/gain behavior and native failure material loss. Public Inscription desks and the active craft are required; crafted tools retain their existing charge-saving chance. Town scribes sell unlimited ordinary supply for80gold. Scrolls require no profession/skill to use and have no tome/refill behavior.

Use the owned scroll and target unidentified gear in your backpack. Only a successful in-place reveal consumes it. Cancellation, invalid/already-known/foreign/ground/equipped targets, missing/moved scrolls, death/frozen state and stale connections leave it intact. Full backpack capacity does not prevent the in-place reveal. Target sessions bind the real scroll, parent, owner and connection; reusing an old target cannot consume another entity.

New magical drops generated through `GearProfiles.FromMonster` begin unidentified; white drops, crafting, Imbuing and ordinary shops remain known. Existing saved identification flags are preserved. T19 must use this generation entry point. Unidentified equipment cannot be equipped; it contributes no affix bonuses even if forced into an equipped layer. Repairs/recharge require identification to avoid rarity/cost previews. Salvage remains allowed, with hidden rarity/ilvl/recovery detail redacted from confirmation.

All normal gear tooltips use the existing saved-state boundary. Native patch0025 also guards single-click labels across equipment families and wand properties appended after the base tooltip. Native Item Identification and identification wands do not reveal Sanctuary state; class actors receive the scroll instruction from ItemID. The server engine and client code are unchanged.

Identification changes only the saved flag on the same serial. Affix definitions/values, native material/maker/wear/charges, quality, sockets, origin and the generated sale offer are retained. Unknown sales still pay10% of that persistent offer without identifying; revealing returns the original full offer rather than rerolling it. Native copy/reload preserves both fields. No new gear save version is required; `SanctuaryEquipment` remains version3, and the new scroll uses generated version0 serialization.
