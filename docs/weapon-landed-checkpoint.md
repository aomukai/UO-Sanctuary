# Landed weapon notification checkpoint

The shared weapon pipeline now exposes a landed-contact boundary before its direct damage notification. This supplies the remaining attachment boundary needed by the prepared Purge proposal, without approving or enabling Purge. Reference remains **D2R Reign of the Warlock 3.3.93847**; coverage stays **218/240 handlers, Warlock9/30; no class certified**.

`PlayerWeaponContact` publishes only from a qualified successful commit, after accuracy/block/dodge decisions. A fully mitigated contact still publishes; misses, blocks and dodges never enter that phase. ResultFlags32 and pair-specific event suppression exclude publication. The existing native/shared `PreparedWeaponEvents` transport publishes at its before-return boundary for already-landed melee/ranged weapon damage. Ordinary spells do not publish. The event is limited to a living player and hostile, living, damageable NPC in the same combat facet; other actor/PvP adapters remain separate.

Subscribers can capture or attach state, and must defer secondary life changes to the later `SkillDamageEvents` phase. A subscribed callback that changes recipient life/deletes or kills it is explicitly refused before the pending health write. With no subscriber, the new notification returns immediately. There is no production consumer, timer, persistence ID or serialization change. Existing Bane post-result and Siphon melee-attempt semantics are retained; this new event does not replace either.

Accepted stage `.local/class-skills/weapon-landed`: Content1, Integration1, source snapshot1, native run1, zero warnings/errors. **15 native markers pass across three boots, two reloads and three saves**. A fixture-scoped listener attaches a prepared Purge mark through a real Cleave release; the same hit sees it in the direct-damage phase and spends exactly one charge. Its explosion damages both the recipient and a nearby monster without overwriting the original hit or recursively publishing. Missed Cleave and explicit miss/block/dodge packets leave no mark; successful zero-life contacts attach without spending a charge; ResultFlags32 and suppression exclude callbacks. The existing ranged weapon damage transport also observes mark-before-damage, while an unrelated spell does not attach a mark. This is not a launched/animated projectile or learned-Purge input test. Generic and typed ordered damage regressions also pass, including actual Cleave lethal reactions.

A distinct original recipient's actually-spent mark, random stream and wounds survive both reloads. Only this persistence control's expiry is held with the existing fixture retention interval; it does not claim natural mark expiry across test boot time. The reaction policy's natural expiry/replacement/chance controls remain in the earlier pinned proposal fixture.

[Evidence](../tools/reference/weapon-landed-native-evidence.json), checked with `python3 tools/record_weapon_landed.py --check`. Existing native/client binaries and installed artifacts/configuration/saves are preserved. No live D2R read or reopen request was made. Shared flashes remain identified placeholders; effects/audio and talent/hotkey icons remain separate.
