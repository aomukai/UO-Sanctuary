# Bone Wall/Prison AI expiry clocks

Reference: **D2R Reign of the Warlock 3.3.93847**, with approved Sanctuary deviations first. Build 4/run 2/audit 2 is accepted within the scope below. This checkpoint covers AI scheduling, not a completed skill/class or the full source death phase. The [native receipt](../tools/reference/bone-barrier-clock-native-evidence.json) binds the tested inputs. No deployment.

New `BoneWallThinkingBody` and `BoneBarrierThinkingBody` save a birth-relative clock. The common pet helper supplies first think25; species skill0 supplies deadline600. A delivered callback requests death only when `deadline < observed frame`; otherwise the next think is15 frames after that observation. Normal uninterrupted callbacks therefore request death at 610. The implementation observes one actual frame per tick rather than replaying missed callbacks, preserving delayed phases such as a think at 600 idling again until 615.

The [source composition](bone-barrier-retirement-source-review.md) executes seven complete bodies across 128 contexts. The native clock matches their deadlines, first events, delivered phases, request frames and counts, with a separate equality600/next615 boundary check. Native UTC/40ms is the existing port's frame-time projection; complete D2 room/stun/leash/inactivity dispatch and current-executable equivalence remain unverified.

Only new roots and their new children opt into the new saved subtypes. Children capture their own birth and nominal600-frame deadline while inheriting the prepared resource recipe; root cleanup remains independent. Historical plain, prepared and maker types retain their layouts and original expiry/timer behavior. Their children keep that historical path too. Source fractional resources, owner-facet wound scaling, maker state and explicit minion links are reused unchanged.

The new types reuse the existing `UsesNativeSummonTimer=false` hook already used by source-timed Ravens, wolves, spirits, vines, sentries and Blade Sentinel. This prevents the native reload-only unsummon timer from pre-empting the AI clock. The historical types keep native timer ownership. The base load hook starts its zero-delay observation after derived fields restore; it no longer decides a derived clock's expiry from the nominal date alone.

Persistence stages three new clock actors (Wall root/child and Prison root) plus historical plain/prepared actors before each save. To inspect the saved fields without changing birth/deadline, the fixture steps the clock to Last595/Next610/Thinks39 immediately; this is an **inspected event fixture**, not naturally elapsed595 frames. Reload verifies actual serials, types, owners, exact clocks, wounds, nominal deadlines, timer ownership and collision links for the whole cohort before stepping610. Native timers then remove the requested-death actors while historical actors remain alive. Both historical fixtures initialize their original native summon-end field. Fresh cohorts are staged for successive saves.

Separate real-input casts use natural observations and verify once-only mana, nominal600-frame deadlines, a strict post600 death request, and actor/collision removal. The log records actual frames/counts rather than assuming every observation must be exactly610. The original maker/casting/allocation/payment/birth/recovery/collision/hostile-firebolt/destruction/Wolf/item/resource scopes remain in the selected suite.

Death requests still enter the previous native deletion/root-cleanup adapter. This change does **not** implement source DEATH-mode transitions, the15-frame DT animation, hidedead/final removal, exact collision-release ordering or the unresolved owner/minion flag graph. Those remain unfinished, as do exact footprint/Prison geometry, acquisition/search/payment gaps, unheld snapshot concurrency, naturally elapsed retirement-save testing and actual old-build byte upgrade. Inspected historical typed fixtures are not an upgrade certificate.
