# Iron Maiden source review

Reference: **D2R Reign of the Warlock 3.3.93847**, with approved Sanctuary deviations taking precedence. This is source preparation for the next Necromancer skill increment. It changes no runtime behavior, handler availability, saved actor or deployed artifact and completes no class.

The pinned skill 76 uses do30/filter3, state 55 and the `domeleedamage` event with callback 4. Radius is 7 source subtiles; mana 5; duration `300 + 60 × (rank − 1)` frames, or 12 seconds at rank 1. There are no aura-stat slots. `calc1 = ln56` gives `200 + 25 × (rank − 1)` percent; calc2/calc3 use one quarter. ResultFlags 16385, combined with the callback’s 32 flag, produce 16417; HitClass 141 is retained. Reuse the existing curse cast/eligibility/duration/rank/creator services rather than creating another area implementation.

The [source receipt](../tools/reference/iron-maiden-source-evidence.json) executes the **complete unchanged event4 and percentage helper**: 8,640 general contexts plus 15,552 legacy Blood Golem-tail contexts under ASan/UBSan. Source files are checked against legacy commit `0c0bbd1e6bef9181a3da1c046523af622a925416`. The matrix covers fractional physical damage, invalid/missing/dead actor and state/statlist guards, rank normalization, creator lookup, player/hireling formula selection, flags/hit class, ordered downstream requests, current source percentage truncation and a synthetic downstream half-damage control. Unit/stat/formula/owner/downstream damage services are declared, rather than presented as the full engine.

The complete, hash-reviewed `SUNITDMG_ExecuteEvents` host calls **attacker DOMELEEDMG first**, then defender DAMAGEDINMELEE, and only then clips physical damage to the defender’s current life. Consequently Iron Maiden consumes **pre-clip fractional physical damage**, before the defender’s Life Tap event and ordinary leech. The host was reviewed, not executed by this probe. The callback itself has no ranged boolean: host event selection determines eligibility. Do not infer obscure missile exceptions from the callback alone.

The reflection callback creates a separate physical packet, calls event1 and then missile/reaction services. It checks that the cursed attacker is a living player/monster with positive physical damage and a matching state/statlist. Player or hireling attackers select the quarter formula; ordinary monsters select the full formula. A missing original caster still reaches the supplied formula service; negative event rank normalizes to 1, while 0 remains 0 in the older callback. Neither establishes that a player can cast rank 0 in Sanctuary.

The complete legacy tail has also been retained rather than silently dropped. Against an evil Blood Golem with valid monster data and nonzero drain, it can heal the cursed attacker/minion owner from the reflected packet after downstream processing. The matrix covers missing data, drain/alignment/live-owner gates, 20 percent recovery, owner-first half share, recipient caps/overflow and overlays. This unusual **enemy-Blood-Golem interaction is not corroborated in the current executable**. Do not enable it as guessed modern behavior; it requires a current reference or an explicitly reported unsupported adapter. The source receipt does not claim a new native healing rule.

The current `NecromancerEffects.WeaponHit` compatibility path uses whole actual life loss after HP commitment, multiplies it with ordinary integer arithmetic, and sends a direct physical hit. It cannot establish fractional pre-clip or event ordering parity. Existing services to reuse are `PreparedWeaponEvents`, `PreparedMonsterDamage`, `PaladinThorns` physical retaliation, `SourcePercentage`, shared mitigation/health/credit and saved curse records. Iron Maiden must run in the attacker damage-event phase **before** defender Life Tap; it must not be moved to percentage Thorns’ later clipped return phase simply because both return damage.
