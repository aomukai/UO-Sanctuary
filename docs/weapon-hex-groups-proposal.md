# Shared weapon Hex group proposal

D2R Reign of the Warlock **3.3.93847** places Hex: Bane, Hex: Purge and Hex: Siphon in self-buff group6, and their three recipient states in group7. These are noncurse states. The owned state table is pinned in the evidence receipt; the older do23 implementation does not establish current replacement behavior for these newer groups. This proposal is an explicit Sanctuary design choice awaiting approval. The Blade Warp best-estimate permission does not authorize this separate change.

Proposed behavior: a successfully paid new Hex replaces the caster's different Hex weapon buff. A successfully applied new Hex replaces a different Hex debuff on that recipient. Buff and recipient groups are independent: changing your weapon buff does not remove a Hex already applied to a monster. Unrelated spells, curses and statuses are untouched. A failed cast, insufficient mana or an ineligible recipient event leaves the previous group intact. Existing same-Hex rank/refresh rules remain; Purge's own unresolved reapplication/charge behavior is outside this group rule.

`WeaponHexGroups` provides the shared group operations. The three existing cast/application helpers accept an explicit prepared opt-in; all default calls retain the previous cross-Hex refusal. Clear operations affect one actor and one group only, without replacing global stores or changing serialized records. There is no automatic combat dispatcher, learned handler or input admission from this proposal. `WeaponHexGroups.Approved` stays false until the decision is recorded.

Focused tests exercise all nine self-buff transitions and six cross-family recipient transitions on actual stored states; failed payment, ineligible events, invalid ability and independent self/recipient groups are controlled separately. Native save/reload tests retain original Warlock/Witch identities, weapon, fractional mana and distinct owner/recipient Hex families. The source and receipt distinguish this proposed policy from current executable parity. No new save format, timer, native/client rebuild or final asset is required.

Remaining after this decision: automatic melee/missile/hextrigger delivery and ordering, learned casting/input, and each skill's other recorded gaps. Siphon's prepared kill-return/stat services already exist. The [pinned-build extractor](https://diabloforfans.com/skill/hex-siphon), checked 2026-11-09, corroborates the table distinction between melee attempts (including misses) and ranged shots that hit; it does not settle group replacement or the protected callback's full behavior. Bane's magic-mastery placement and Purge's explosion/charge consumer remain separate tasks.

Effects/audio and talent/hotkey icons remain in their independent registers. Installed build, saves and configuration are preserved. Handler coverage remains **215/240**, Warlock **6/30**; this proposal adds no completed talent or class.
