# T19 — Production gear drops and Magic Find

Implemented, verified and deployed 20 October 2026 JST. User-confirmed scope: the existing mapped Normal reward roster, ordinary white bases for inferior/superior white outcomes, and **empty Set/Unique outcomes** until actual item systems exist. Nothing rerolls or redistributes those probabilities. This is the Normal encounter cohort, not a claim of full D2 item-system/world parity.

The subsequent [Nightmare/Hell extension](t19-difficulties.md) adds persistent spawn identities and difficulty-specific stats/XP/loot. The Normal catalogue and its recorded scope below remain unchanged; world placement is deferred by user decision.

## Drop selection

All 324 enabled common creature types retain the existing T10 reward policy; 406 explicit exclusions remain. Nine enabled types have no source treasure class and produce no gold/gear. Existing native-loot suppression remains: original corpse inventory is cleared once before authored rewards. The saved reward-life claim precedes all consumers and blocks repeated callbacks/revived lives. XP success, level99, player distance and owner life state do not gate loot; controlled/summoned killer credit resolves to the owner. Vendors, controlled/summoned/animated victims, no-awards and uncredited/nonclass victims remain excluded.

Gold and gear share a single terminal draw through the 104 existing reachable treasure classes. All have one positive pick and zero quality modifiers; the extractor fails if those bounded source assumptions change. Gold chance/amount/Gold Find remain T10's. NoDrop and non-gear branches retain their original weight. A Skeleton's top class still has NoDrop 100, gold 21, equipment 16, junk 21 and good 2 out of 160; the actual supported item rate also reflects the selected nested base and reserved outcomes. There is no connected-player scaling or automatic pickup.

`tools/build_gear_drops.py` verifies all source hashes and the shared gold extraction, synthesizes the 34 reachable item-type pools in three-level bands, and retains empty source classes such as bow15/bow21. Source item-type rarity weights choose the D2 base. Only then is one currently mapped UO appearance selected uniformly, so several UO types sharing a base do not inflate its chance. No current mapping means no item. Explicit exclusions preserve gems, charms, legacy runes, potions, scrolls, keys and other later systems without creating alternative supply paths.

The catalogue contains 225 mapped base identities / 529 UO variants across Normal/Exceptional/Elite. Only source classes reachable from the selected Normal roster are enabled; current pool levels reach 39 and do not naturally select Elite bases. Higher-difficulty/world expansion remains separate work. Ten deferred exotic crafting recipes are not enabled by a drop mapping.

An item receives Drop origin and the actual resolved monster level as ilvl. Its stored source base determines stats, tier and affix level; existing tier equip floors, Strength/Dexterity and class rules still apply. New drops get no crafting material perks, maker mark, crafting-quality bonus or sockets. White gear is known; Magic/Rare is unidentified. Same-serial identification, 10% unknown resale and matching-tool salvage use T18/T11/T16's existing guarded paths. Gear save version stays 3.

## Magic Find

Numeric `mag%` affixes and stored gold-armour `magic-find` rolls stack while equipped, identified, working and in an active slot. Broken, carried, cosmetic, suppressed-slot and unidentified gear contributes zero. The credited owner's death-time total is used for pet kills; equipment moved onto the dead owner's corpse no longer counts. Existing saved material rolls become active without rerolling them. The character panel replaces its unused Luck readout with the actual MF percentage and explanatory tooltip; shared stat protocol version 5 appends one field without changing existing indices.

The independent quality checks run **Unique → Set → Rare → Magic → ordinary white**. Set/Unique successes stop with an empty result. Rings/amulets retain the source's always-Magic behavior after the higher checks. MF does not change treasure/base selection, item level, affix eligibility or affix-value ranges. It improves quality chance; it does not guarantee a supported item while reserved outcomes remain empty.

For each quality, start from `(source ratio − trunc((ilvl−qlvl)/divisor)) × 128`, multiply by 100 and divide by `100+effective MF` with the source integer rounding, then apply the source minimum denominator. A random ticket below128 succeeds. MF 0–10 is linear; above 10, effective MF is `floor(250×MF/(250+MF))` for Unique, 500 for Set and 600 for Rare. Magic stays linear. Source class-specific and exceptional/elite ItemRatio rows are selected separately. Ordinary white subqualities are coalesced by explicit user decision. All numerical live affixes retain ordinary legal random values; unsupported effects remain filtered out.

## Evidence and reproduction

Data tables are pinned LoD 1.13 commit [45112569](https://github.com/fabd/diablo2/tree/45112569deb9384738ccafe5c24ebbb71f41c7c9/code/d2_113_data); ItemRatio is added to the existing SHA-256 manifest. Algorithm evidence is independently implemented from D2MOO commit [80169009](https://github.com/ThePhrozenKeep/D2MOO/tree/80169009eea696f83d949cc3a6f1bc9302f2fd53): [treasure/quality checks](https://github.com/ThePhrozenKeep/D2MOO/blob/80169009eea696f83d949cc3a6f1bc9302f2fd53/source/D2Game/src/ITEMS/Items.cpp), [automatic base pools](https://github.com/ThePhrozenKeep/D2MOO/blob/80169009eea696f83d949cc3a6f1bc9302f2fd53/source/D2Common/src/DataTbls/MonsterTbls.cpp) and [ratio selection](https://github.com/ThePhrozenKeep/D2MOO/blob/80169009eea696f83d949cc3a6f1bc9302f2fd53/source/D2Common/src/DataTbls/ItemsTbls.cpp). Algorithm URLs/hashes are recorded in `tools/reference/gear-drop-algorithm-sources.json`. Blizzard's [Magic Find guide](https://classic.battle.net/diablo2exp/items/magic/magicfind.shtml) describes its quality-only role and diminishing returns; exact arithmetic here follows the pinned reconstruction.

Reproduce with `python3 tools/fetch_balance_sources.py --destination <source>`, then `python3 tools/build_creature_gold.py --source-dir <source> --check` and `python3 tools/build_gear_drops.py --source-dir <source> --check`. The committed catalogue and pins are runtime evidence; research caches are optional. Real Set/Unique implementation, distinct dropped-white quality bonuses, later-system branches and Nightmare/Hell/boss encounters need their own authored expansion; do not renormalize this catalogue to fill gaps.
