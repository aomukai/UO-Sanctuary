# Hex Bane mastery and melee timing proposal

D2R Reign of the Warlock **3.3.93847**, with approved Sanctuary deviations first. Bane's ordinary cast/stat/target-state implementations already exist, and shared Hex replacement is approved. This separate mastery/timing proposal awaits a decision; it does not reopen the group rule. Bane remains unavailable in normal input, with coverage **216/240**, Warlock **7/30**.

Proposed rule: use the pinned table and hard synergies to compute FP256 magic endpoints, apply the caster's magic mastery at cast time, then truncate to the whole points stored by enma/exma. At each weapon hit, the existing weapon pipeline applies the attacker's current magic mastery again to that stored magic. Changing gear after casting changes the delivery-stage mastery without rewriting stored cast damage. With unchanged +10% mastery, the two stages give about +21% before whole-point rounding. No physical critical multiplier is added to the magic component.

For the recipient Hex, finish the melee hit/block/dodge result first, then apply its defense/attack-rating penalty. A miss still applies the Hex, while the penalty can help only later attacks. Ranged delivery reuses the successful weapon event path; advanced hextrigger producers keep their separately qualified entry. This does not guess their unfinished skill-specific conditions.

The older complete melee event routine copies an existing combat result and checks reach before dispatching domeleeattack for hits and misses. That supports the proposed post-result ordering. However, the older spell endpoint mastery helper omits magic even though its weapon fill supports passive magic mastery. It cannot establish the new Warlock cast-stage behavior. One bounded read of current selector28cc10, directly linked by the retained current maximum getter, found it protected. The 560 bytes read were identity anchors, with no helper code forced and no unchanged retry. [Source review](../tools/reference/hex-bane-damage-source-review.json).

`HexBaneDamageProposal` contains the explicit cast-stage arithmetic and qualified post-result receiver. It is not connected to a learned cast or automatic combat producer. Native checks feed its prepared stored magic through the actual shared weapon enhancement/mitigation/health path, using explicitly supplied current-mastery percentages and the exact shared mastery arithmetic, then actual weapon mitigation/HP. The existing gameplay buff remains the original zero-mastery registration; the candidate plan is an explicitly supplied test fixture record, not a new live buff or save format. Existing nonzero-mastery cast refusal stays in place until the decision is implemented. Entropy Locket remains intentionally gated by its unfinished Miasma Chains on-strike proc;this candidate does not bypass that item gate or claim a live mastery-gear test.

Effects/audio and talent/right/quick icons remain in their existing separate registers. No new artwork, native/client patch, timer, gameplay serialization or deployment is needed for this proposal. The working installed build and existing saves are preserved. Exact current callback36 order/special overrides and mastery selector semantics remain unverified; these proposed choices are not claims of recovered current code.
