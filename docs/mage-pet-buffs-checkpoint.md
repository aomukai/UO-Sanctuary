NPC Enchant shares the existing effect constructor, stacking/snapshot/expiry storage and weapon consumers while bypassing the player's enhancement path. Player Enchant retains its original enhancement and duration behavior.

A Fire Mage with20 hard Raise Skeletal Mage points automatically applies level20 Enchant to unenchanted owner/allies within the existing native targeting range/LOS when its AI first enters an offensive skill action. It uses the Mage as the effect source and takes no extra animation, action or mana. The combat latch prevents continuous scans and repeated buff refreshes; a later fight can enchant newly arrived allies. Existing enchantments keep their original snapshot/timer. Ordinary recovery does not restart combat; suspension/reload begins a new combat observation. This is the approved combat-start behavior, not a new generalized encounter system.

An Ice Mage with20 hard points has intrinsic, always-on level20 Frozen Armor. It reuses the Sorceress cold-armor constructor and shared defense/freeze consumers. NPC defense now reads the same armor percentage; successful physical melee-hit notifications can freeze the hostile attacker with the Mage as source. Ranged and zero-physical-loss notifications do not trigger it, matching the existing armor consumer. Training/respec/relearning updates the existing pet immediately without recapturing birth stats, healing or starting a refresh timer. A soft bonus alone does not unlock it.
