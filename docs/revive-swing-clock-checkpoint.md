# Original Revive ordinary A1 clocks

Reference: **D2R Reign of the Warlock 3.3.93847**, approved Sanctuary deviations first. This provides owned animation metadata and a prepared clock calculation; native AI swing scheduling, pending actions and public equipped casting are not enabled by this component.

The builder compares all 751 monster Code/model BaseW tokens with the owned, hash-pinned monstats/monstats2 files and parses all 3,661 records from the already verified owned AnimData.d2. There are 3,631 unique animation codes. Some duplicate codes have different metadata; no first/last-record choice is invented. The runtime catalogue admits 436 single-melee-action A1 rows. It retains explicit reasons for the other 315: 161 missing records, 147 multiple/nonmelee-event paths, two dual-wield sources and five sources using ambiguous A1 records. Ambiguous variants are preserved in the source receipt. A missing record is not replaced with a guessed duration.

The reviewed older composite branch selects a monster's configured BaseW rather than a player's weapon-animation class. Current metadata corroborates skeleton SKA11HS (16 frames, speed224, action10) and zombie ZMA1HTH (16,256,9). This is source/current-data evidence, not proof of every modern dynamic animation lookup or mode conversion. Reuse of the existing attack-rate and initial frame-event services keeps those limits explicit.

FrozenCombatBase appends an optional WeaponSpeed value. Newly captured weapon bases preserve their pinned base speed; nonweapons record zero. Historical missing values remain null and retain existing stat/event profiles, while the new timing consumer refuses missing weapon-speed input. Validation rejects invalid numeric domains and nonweapon speed injection. No loot item is recreated or read after death.

ReviveSwingClock reads the original source identity, reduced creature level, frozen item IAS from all three swing slots and captured weapon base speed. It combines them with the existing live NPC haste/slow supplier, SourceAttackRate and SourceAnimationEvents. Player/owner IAS and UO weapon-delay calculations are not substituted. Multiple weapons, dual-wield sources, missing/ambiguous/nonmelee metadata and skipped/duplicated action events refuse explicitly. Clock queries neither consume the actor RNG nor change health/resources.

A new native source harness reuses the hash-verified generated prefix containing the complete unchanged A1 rate predicate, writer and initial scheduler. It runs 97,664 contexts over all 436 admitted rows, signed IAS, actor rates and weapon-speed inputs. ASan/UBSan exit cleanly. The C# comparison checks exact speed, action and end events, including explicit refusal if an action is absent. Skeleton's ordinary baseline is action12/end19; zombie is action9/end16. This is legacy algorithm parity with owned metadata, not a modern executable or complete controller certificate.

A real retained Skeleton uses an ordinary Axe and Goldwrap, with live base speed/IAS captured before its independent loot is deleted. Its clock, immutable inputs, wounds, no-query-RNG behavior and historical missing-speed/multiple-hand refusals repeat across reloads. The first fixture mistakenly counted only swing1 even though Goldwrap uses swing2; the consumer already used all three. That failed run is retained, and the fixture now compares all three live slots.
