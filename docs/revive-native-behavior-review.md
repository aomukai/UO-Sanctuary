# Native Revive behavior review

The [approved policy](../tools/reference/revive-native-behavior-policy.json) permits reuse where native behavior fits D2 combat and replacements where it does not. These are per-behavior implementation decisions under that policy, not a claim that every UO ability is a D2 counterpart. The reference stays D2R 3.3.93847; the existing relative-strength classification, loot separation and no-expiration decisions remain in force.

| Behavior | Decision and evidence | Remaining work |
| --- | --- | --- |
| Original actor identity | Keep the original object, serial, type, appearance and compatible AI role. [Activation](../tools/reference/revive-native-activation-evidence.json) verifies in-place ownership and independent corpse loot. | Validate individual special AI/state paths; preserving identity does not require retaining every UO mechanic. |
| Following the owner | Keep native automatic Guard following. [Control acceptance](../tools/reference/revive-native-control-evidence.json) verifies natural following without a replacement brain. | Follow/pathing proof is not complete attack-mode or spell proof. Review each role's combat loop. |
| Taming commands, loyalty and stabling | Adapt: class minions use non-commandable identity and cannot be stabled. [Control](../tools/reference/revive-native-control-evidence.json) and [stabling](../tools/reference/revive-native-stabling-evidence.json) verify ordinary pets remain unchanged. | Retain the exclusions when adding new supported native types. |
| Offline/death behavior | Adapt to shared class-minion suspension and owner-death removal. [Lifecycle](../tools/reference/revive-native-lifecycle-evidence.json) verifies real socket closure, protected parking, queued-breath cancellation and return of the same NPC. | New special dispatchers must obey the same CanAct/lifecycle guard. |
| Life and ordinary combat stats | Adapt to D2 corpse HP, lower-caster scaling, captured Mastery and source velocity, using existing combat hooks. [Source life](../tools/reference/revive-source-life-evidence.json) is accepted; native combat-stat acceptance is in progress. | Complete original retained-stat/item dependencies, Summon Resist/events, regeneration, respec and facet replanning. |
| Equipped items | Keep the physical originals as loot; preserve their combat effects independently. [Accepted-death capture](../tools/reference/revive-before-death-native-evidence.json) verifies separate immutable numeric snapshots. | Bind complete NPC item/stat/proc consumers; a captured property is not an applied effect. |
| Generic native ability cooldowns | Review the existing native death reset as a candidate adapter. Accepted-death tests establish capture before clearing and zero live cooldown after death. | Decide and verify the supported behavior when enabling each ability. Archived remaining duration does not itself require restoring that clock. Do not label all special attacks blocked solely because an archival clock is not replayed. |
| Dragon breath and other special attacks | Review individually. Retain compatible effects and adapt damage, rate, resource use, targeting and interruption to D2 combat as needed. | Parked queued breath is tested; complete active damage/rate/resource behavior is not. Do not infer active combat acceptance from the parking test. |
| UO spells or effects that conflict with D2 | Adapt or replace the conflicting part using existing D2 mechanics where suitable. | Identify the actual conflict and the chosen replacement per role. Do not invent a replacement merely because the original is unfamiliar. |
| Inherited sunder | Unimplemented; supplied nonzero values refuse explicitly in the combat-plan adapter. | Add a real immunity consumer and establish complete accrued-stat/active-charm collection before enabling it. |

This review removes a design ambiguity; it does not enable learned Revive or automatic corpse retention. Source eligibility, cast/placement/mode/payment, remaining combat effects and supported-role acceptance still require implementation. Unsupported cases must carry a reason and must not stop work on unaffected skills. Final effects/audio and talent/hotkey icons stay in their separate placeholder registers.
