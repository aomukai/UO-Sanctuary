# GenericPet special AI callbacks

2026-11-09 JST. Mechanical reference: **D2R Reign of the Warlock 3.3.93847**. Coverage remains **213/240 handlers, Warlock 4/30; no class certified**. Both table-qualified special callbacks are implemented over existing policies and explicit leaves. Automatic AI and learned summon/Death Mark admission remain unfinished.

`GenericPetAiOverrides.Run` follows complete table callback 0 (`4b63d0`, 782 bytes) and callback 1 (`4b66e0`, 933 bytes). Both require control state 0 and raw control word +10 equal to 1. They resolve the owner through the actor's own control pointer, initialize a separate default frame, try an over-leash follow, and otherwise call the supplied default AI. When the actor is in mode 1 or its moving predicate succeeds, they run the existing search with mask/explicit target **0/0**. A zero high half of selection word +48 removes type-2 events, retries follow, and idles 15 frames if follow fails. Other event types remain. Callback 0 can run without an owner and does not filter owner life first; callback 1 rejects a missing/inactive owner and invokes `392be0(game, actor, 0, 1)` only if the actor remains active. That last helper is an explicit missing-owner action, with no invented deletion/reset semantics.

The callbacks use a different initializer, `4b10b0` (360 bytes), from the previously qualified `4b0b90`. Its implementation reuses the existing empty-default parameter representation and player-owner survey, then retains the source's explicit 784/2500/60/0 prefix and −1/0/0 transient memory. It does not consume a target command, query life percentages or publish saved control words. The existing coordinate decoder, squared-distance routine and timed-event store are reused. Native scratch fields that this initializer does not write remain unqualified; search/score bindings must not manufacture their values.

The two actual override rows are published separately from startup/control production. `GenericPetAiOverrideTables` loads the pinned flags and function identities for indices 0 and 1. The data builder authenticates the already captured table against the pinned executable. No birth defaults are published. The original demon entry cohort selects both table indices as clearly identified fixtures and supplies raw header word +10 = 1 and source mode 1 explicitly. Native serial/owner resolution, the existing owner survey and registered default root use their existing bindings. Its post-root search result is still an explicit fixture. These tests do not establish an authentic Field14 or header startup value.
