# Complete Sigil: Death rule proposal

**Awaiting approval.** Prepared 2026-11-14 JST against **D2R Reign of the Warlock 3.3.93847**. This is an explicit Sanctuary adaptation for unavailable event33/34 bookkeeping and hidden explosion do153. The skill remains unavailable: **220/240 handlers, Warlock11/30; no class certified**.

Known pinned fields supply skill400, hidden403, the shared Sigil launch, six-frame pulses,12-frame recipient duration, mark radius4/6/8source cells at ranks1/10/20,100%mark chance, and the hidden70–120%,50%fire,8source-cell explosion parameters. State194 has no owned curse/group flag. The [reference gap](../tools/reference/sigil-death-reference-gap.json) remains unresolved; the prepared implementation does not identify or register the unlinked event table or claim recovered current-binary behavior.

The proposed complete rule is:

- Use the existing Warlock SC/FCR ground/target cast and shared Sigil placement, one-slot replacement and lifecycle. Pay the pinned table cost once at successful release:10mana at rank1. Failed payment/placement or canceled windup preserves the previous marker. Learned left/right/quick acceptance follows approval; the prepared candidate tests the common paid marker transaction rather than authenticated learned Death input.
- Snapshot rank and the owner's Magical Penetration/elemental modifiers when creating the marker, following the approved temporary-actor snapshot preference. Do not rewrite an existing marker from later gear or potion changes. Old saved Death markers without captured modifiers remain nonreactive; no migration fills their unknown snapshot.
- Each actual six-frame pulse claims its saved frame before callbacks, then marks living damageable hostile NPCs in serial order within the inclusive primary radius and shared16-height limit. Use existing aura/source identity and safety rules, excluding source species bosses; do not replace that predicate with native elite grade. Add no extra recipient LOS to the primary pulse. The100%mark chance needs no chance draw.
- The mark is independent of ordinary curses, other Sigil recipient effects and the caster's later marker replacement. Its lease lasts12frames(0.48seconds). Weaker rank does not replace it. Equal rank refreshes the lease while retaining the original creator, captured modifiers and stream, including another equal-rank caster. Stronger rank replaces creator/rank/modifiers while retaining the existing stream. A new mark after expiry gets a fresh stream. This is a per-mark adapter stream, not a claim about global D2R unit RNG interleaving.
- Death by any cause claims the active mark exactly once. There is no extra applying-hit requirement, damage contribution counter or guessed event34 health bookkeeping. Expired marks and deaths without a usable corpse do not explode. Queue processing starts after native corpse creation and death/ownership cleanup return. Eligibility at death is retained across that short queue delay; a later marker pulse cannot replay the claimed death.
- The corpse must pass the existing physical availability, selectable, unowned, unshattered, unused and Rest-in-Peace rules and contain the original captured source base-life identity. Use its pinned base HP before spawned-life/player-count/elite adjustments. Do not reconstruct missing life from its corpse item serial or current NPC stats. **Automatic marked death ignores loot ownership/access checks**, unlike manual corpse skills; it neither takes nor transfers items. Protected loot remains protected and present. The initial diagnostic exposed why manual loot rights cannot establish an automatic any-killer trigger.
- Roll one FP256 amount from70%inclusive to120%exclusive of that base HP using the saved mark stream. Split it50%physical/50%fire, with existing integer percentage rounding. Apply both components across the entire inclusive4-native-tile circle(raw8source cells), with shared height/safety and LOS from the corpse. There is **no caster/corpse level ratio and no smaller physical inner radius**. This deliberately reuses generic percentage/RNG services without substituting old do55 packet semantics.
- Apply no fire/mastery or weapon enhancement to the base corpse components. Captured potion additions use the existing shared elemental potion helper and their captured masteries. Each recipient uses its current independent defenses. There is no accuracy/block roll, weapon critical/leech, hit recovery or on-strike/weapon-kill proc from this secondary packet. Pair suppression prevents its direct HP packets from triggering Purge and other damage reactions; ordinary death/reward handling still runs.
- Validate supported receivers before corpse reservation or explosion damage. An unsupported special receiver returns an explicit fault, leaving the corpse and burst HP untouched. The original death claim stays final. Missing source base life also returns a fault. Production integration must surface those faults; it must not invent an NPC base or silently claim complete receiver support.
- Reserve and consume the corpse before applying the burst. Preserve its loot. Damage can kill other marked NPCs; enqueue their deaths into the same FIFO and drain each once, after its native death cleanup. This explicitly permits corpse chains without recursive stack growth or duplicate corpse consumption. It is a defined adaptation, not proof of the protected skill-node recursion behavior.
- A queued explosion requires its creator alive, online, in the corpse's original facet and outside an actual safe area when processed. Logout, facet separation or owner death cancels that queued reaction without consuming the corpse or saving a replay. Marker lifetime continues under the already-approved Sigil lifecycle; there is no catch-up pulse. Queue jobs are transient action work, not persisted future attacks. A crash/save-load boundary before a job runs does not replay it.
