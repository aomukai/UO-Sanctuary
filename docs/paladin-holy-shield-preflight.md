## Recast discrepancy to resolve

The pinned Holy Shield state is 101 and has no group entry. In the unchanged shared `sub_6FD10EC0`, an existing list with the same state and skill retains its list at equal rank (refreshing a nonzero deadline), refuses a lower incoming rank, and is replaced at a higher rank. The existing compiled group-zero cases exercise this branch. In contrast, current `HolyShields.Cast` always replaces its record, including a weaker recast. Record this discrepancy explicitly. Confirm the outer start/do/payment contract and modern applicability before choosing whether a refused weaker recast spends mana or animates; the shared list helper alone does not settle that outer behavior. Atomic restore and snapshot safety can proceed independently.

## Composed start/payment preparation

The [new compiled composition](../tools/reference/holy-shield-cast-source-evidence.json) reuses the unchanged do18/list and generic wrapper bodies with the actual start36 shield gate across **480 cases**, clean under ASan/UBSan. In the ordinary learned path, a valid inventory/shield and readiness check lead to one mana-consume call at start. The current pinned route has a nonnull start36 and UseManaOnDo=0, so its do wrapper does not charge again. Consequently, a weaker same-skill effect can be refused after a successful already-paid start. Equal rank refreshes and higher rank replaces. Losing the shield between start and do does not itself prevent the do18 body; the shield-dependent consumers remain separate. Existing group1 cold armor is preserved.

This resolves the bounded older payment/callback composition, not the complete modern player-mode/input path or real mana-helper arithmetic. The outer bypass flag, rooms, list/store/formula and inventory are declared services; no charged-item permission or animation behavior is inferred. Native implementation should preserve the start/do distinction and add actual input/equipment/cancellation/payment tests instead of moving the rejection before payment merely because another buff has no start callback.
