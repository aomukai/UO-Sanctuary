# Live pet freeze and stun binding

Reference: D2R Reign of the Warlock **3.3.93847**, with approved Sanctuary deviations first. This closes the two live status inputs needed by the shared monster event router and AI preprocessing. It does not admit learned summons or automatic AI.

`GenericPetNativeControlStates` reads the existing `NamedControl.FrozenRemaining` and `CombatStuns.Remaining` providers. Pinned metadata identifies source state 1 as `freeze` and state 21 as `stunned`. It supplies those two bits to the existing event router, and replaces only those bits when projecting a preprocessing unit. Unrelated state bits, flags, mode, path and movement objects are retained. Unsupported selector aliases, state counts and nonextended input roots refuse explicitly.

This is a native projection for these two consumers, not a full D2 stat-root producer or an implementation of all status states. Native `Frozen`/`Paralyzed` movement flags do not establish either source state. The existing post-freeze AI waiting interval is also separate: removing freeze clears its active state even while the existing waiting provider remains true. That waiting policy, source state 54/143, special AI selection and other state consumers remain separate work.

The native test uses additional original Goatman, Tainted and Defiler actors with Warlock/Witch owners and explicitly supplied typed commands/control words. The shared frame pump and event dispatcher route their real freeze state through the source router. A frozen AI event does not reach entry. A real stun reaches the full entry but its live preprocessing schedules an AI event three frames later without calling the root or publishing control words. After stun removal, frames before that deadline do nothing; the deadline invokes exactly one existing full entry/override/default root. Birth snapshots, fractional wounds, mana and typed commands remain intact.

Only the existing effect producers are staged in these component tests; freeze mitigation and stun duration selection are not bypassed in player gameplay. The test clears its own post-freeze waiting fixture before exercising stun, rather than defining new gameplay for that waiting interval. World/path/search/follow inputs other than these two live statuses remain explicit. The new entry-test option supports the expected early preprocessing return; existing callers keep their prior default path.
